# 03. 넷 타입 등록과 비트 직렬화

[목차](network.md)

## 1. 개요

이벤트(`*NetEvent`, `*Event`)와 상태(`*NetState`, `*State`)는 모두 **이름·hash·객체 크기·직렬화 비트 수**를 가진 타입으로 정적 초기화 때 등록됩니다. 각 타입은 공통 vtable 모양(reset/equals/copy/비트 수/write/read/getName)을 가지고, write는 필드를 **비트 단위로 양자화**해 씁니다. 이 문서의 공식은 원본 함수를 unicorn으로 실행해 재구현과 비교했습니다.

## 2. 자료

### 3.2 vtable 슬롯 [판독]

BulletShooter(`0x71056284f0`)·PlayerNetState(`0x710562e018`) 등 공통:

| 슬롯(오프셋) | 용도 | 근거 |
|---|---|---|
| 2 (+0x10) | reset (필드 0으로) | 본문 |
| 6 (+0x30) | equals | 필드별 비교 |
| 7 (+0x38) | copy | 필드별 복사 |
| 10, 11 (+0x50, +0x58) | 비트 수 반환 | `mov w0,#0x6c` |
| 12 (+0x60) | **write** | writer 호출 |
| 13 (+0x68) | **read** | reader 호출 |
| 14 (+0x70) | getName | 이름 문자열 반환 |
| 15 (+0x78) | 타입 hash 반환 | `mov w0,#hash` |

생성자는 `[obj]=vt, [obj+8]=vt+0x90, [obj+0x10]=vt+0xb0, [obj+0x18]=vt+0xf0` 네 개의 vtable 포인터를 씁니다(다중 상속). 필드는 `+0x20`부터입니다. 두 번째 인터페이스(vt+0xb0)에도 write/read 쌍이 있어(예 0x71023e0de8/0x71023e11cc) 다른 스트림(리플레이 기록 등)용으로 보입니다 **[추정]**.

### 3.3 Writer/Reader API [판독 + 실행]

스트림 객체 `S`: `S+8` = writer(또는 reader) 객체, `S+0x10` = 문맥, `S+0x18` = 정수(패딩 호출 인자).

| writer vtable | 호출 모양 | 비트 | 근거 |
|---|---|---|---|
| +0xa8 | `(w, ctx, &value, nbits)` | nbits | 대부분의 필드 |
| +0x60 | `(w, ctx, S+0x18, u8)` | 8 | 패딩 바이트 |
| +0x70 | `(w, ctx, S+0x18, u32)` | 32 | VersusStartClockEvent |
| +0x78 | `(w, ctx, S+0x18, u64)` | 64 | WallaObjActivateEvent |
| +0x90 | `(w, ctx, S+0x18, s32/f32)` | 32 | GachiasariClam* |
| +0xb0 | `(w, ctx, ptr, nbytes)` | 8×nbytes | 문자열(128 B) |
| reader +0x48 | `(r, ctx, &out, nbits)` | nbits | read 함수 |

+0x60/+0x70/+0x78/+0x90 비트 수는 이 값으로 가정하고 원본 write를 실행했을 때 등록 비트 수와 맞았습니다(§6) **[실행]**.

### 3.4 실제 비트 writer와 패킹 순서 [판독 + 실행]

이벤트 큐잉(0x71018b8968)·디코드(0x71018b84d4)가 스택에 만드는 writer 객체의 vtable은 `[GOT 0x7105790db8]+0x10 = 0x71057209c0`입니다. 슬롯 +0xa8 = 0x7103582678(writeBits), +0x60 = 0x7103581630(u8), +0x70 = 0x7103581838(u32), +0x78 = 0x7103581a88, +0x90 = 0x7103581ff8, +0xd8 = 0x71035827ac(마지막 부분 바이트 내보내기).

```
writer: +8 acc(u8), +9 nacc(u8), +0xa 닫힘, +0xb 사용됨, +0x10 sink, +0x18 총 비트 수
writeBits(w, sink, src, n):           // 0x7103582678
  for done = 0; done < n; done += k:
     byte = src[done >> 3];  k = min(8, n - done)
     take = min(k, 8 - nacc)
     acc |= (byte & ((1<<take)-1)) << nacc;  nacc += take
     if k - take > 0:                  // 바이트가 넘치면
        sink->vt[+8](sink, &acc, 1)    // 1바이트 내보냄
        acc = (byte >> take) & ((1<<(k-take))-1);  nacc = k - take
  total += n
```

- **LSB 우선**: 값은 리틀엔디언 바이트 순서로 읽고, 각 바이트의 하위 비트부터 출력 바이트의 빈 하위 비트에 채웁니다. 즉 스트림의 i번째 비트 = 출력 바이트 `i>>3`의 비트 `i&7`.
- **지연 내보내기**: 8비트가 꽉 차도 바로 내보내지 않고, 다음 쓰기에서 넘칠 때 또는 +0xd8 마감 호출에서 내보냅니다(`nacc == 8` 상태가 존재). 스트림 결과는 즉시 내보내기와 같습니다.
- 스칼라 슬롯(u8 +0x60, u32 +0x70)도 같은 누산기를 공유합니다 — 바이트 경계 정렬을 하지 않습니다.

검증 **[실행]** `web/tools/network_bitpack.py`: 원본 writeBits에 무작위 (값, 1~32비트) 열 3,000세트 → 출력 = 파이썬 LSB 우선 패커(불일치 0). u8/u32 슬롯 혼합 750세트 불일치 0. 기본 PlayerNetState(위치·스탬프 일부 설정)를 원본 write + 원본 writer로 직렬화 → 546비트 = 68바이트 + 대기 2비트, 바이트열이 스텁 로그를 파이썬으로 패킹한 것과 같음. 결과 `analysis/network/bitpack_result.json`.

### 3.5 이벤트 메시지 헤더 비트 폭 [판독 + 실행]

이벤트 메시지 스키마(0x710129ad24, 타입마다 0x50 B)는 요소 3개를 순서대로 가집니다: ① 타입 등록 엔트리(payload, 타입 write) ② GameFrame 값 요소 ③ LifeNumber 값 요소. 큐잉(0x71018b8968)은 이 순서대로 같은 writer에 씁니다. 값 요소는 0x71012a0168이 `NetEnlValueParam.ValueType` 이름의 해시(0x7100f7694c; `U32` = 0x90695c2f, `U64` 0x78818d21, `S32` 0x74d10ee2, `F32` 0x67a3f9ea, `Bool` 0xe74428f2 — 원본 함수 실행으로 계산)로 분기해 만듭니다.

`U32` + `ParamU64{min,max}` 요소(vtable 0x7105573fd0):

```
write 0x71012a4080:  q = v < min ? 0 : min(v, max) - min;   nbits = 64 - clz64(max - min);  writeBits(q, nbits)
read  0x71012a40dc:  v = readBits(nbits) + min
```

범위가 없는 `U32`는 vtable 0x7105573fa0, 32비트입니다.

| 헤더 요소 | 범위(데이터) | 비트 | 비고 |
|---|---|---|---|
| GameFrame | 0~8,388,607 | **23** | 8,388,607 초과는 8,388,607로 포화(약 38.8시간) |
| LifeNumber | 0~15 | **4** | 송신측이 이미 `& 0xF` |

검증 **[실행]**: `network_bitpack.py` 검사 4 — 0x71012a4080/0x71012a40dc를 두 범위로 실행, 비트 수·포화·왕복 모두 식과 일치.

따라서 이벤트 1건의 비트 = payload(타입 write 비트) + 27. 큐 항목 비트 수는 스키마+0x48 상한으로 잘립니다(0x71018b8968) **[판독]**. pia 계층의 패킷 헤더·묶음 단위는 이 위에 붙습니다 **[미판독]**.

## 4. 양자화 공식 [판독 + 실행]

모든 연산은 f32, 정수 변환은 **0 방향 절삭**(`fcvtzu/fcvtzs`)입니다. "부호+크기" 형식은 크기를 상한에서 자르고 음수면 최상위 비트를 세웁니다.

### 위치 성분 `Q17` (17비트)

```
enc(v):  a = |v|;  m = (u32)(a * 0.00390625f * 65535.0f);  if m >= 0xFFFF: m = 0xFFFF
         return m | (v < 0 ? 0x10000 : 0)
dec(q):  f = (q & ~0x10000) / 65535.0f;  return (q & 0x10000) ? f * -256.0f : f * 256.0f
```

범위 ±256, 단위 256/65535 ≈ 0.0039063. 256 이상은 ±256으로 포화합니다. 위치·탄 발사점 등 대부분의 좌표에 씁니다.

### 방향 `DIR21` (0x7102905b38) / `DIR25` (0x7102905f44)

```
n = normalize(v)                 // 길이 0이면 정규화 생략
pitch = asinIdx(n.y) → 라디안    // 0x7101252530, 표 기반
yaw   = atan2Idx(n.x, n.z) * 1.4629181e-09 (= 2π/2^32), (-π, π] 로 접기
DIR21: P = sgnmag(|pitch|/(π/2) * 511, 9비트), Y = sgnmag(|yaw|/π * 1023, 10비트)  → 쓰기 순서 P(10) 다음 Y(11)
DIR25: P = sgnmag(|pitch|/(π/2) * 2047, 11비트), Y = sgnmag(|yaw|/π * 4095, 12비트) → P(12) 다음 Y(13)
```

원본 식은 `(|θ|/π) * 1024.0 * 0.0009765625 * 1023.0`처럼 2의 거듭제곱을 곱했다 나누는 형태라 값은 `|θ|/π*1023`과 같습니다. 각도 단위: DIR21 ≈ 0.176°, DIR25 ≈ 0.044°.

`atan2Idx`(0x7101252998)는 sead식 128구간 보간 표(`[0x7105794808]`, 항목 8 B = {u32 각도 인덱스, f32 기울기})를 씁니다. `Math.atan2`/`Math.asin`으로 바꾸면 **3,000개 무작위 방향 중 99.3%가 같은 값, 나머지는 1 LSB 차이**였습니다 **[실행 대조]**. 디코드 쪽은 sin/cos 표(`[0x7105794810]`, 항목 16 B = {sin, dsin, cos, dcos}, 256구간)를 씁니다.

축 규약: yaw = atan2(x, z) — **+Z가 yaw 0, +X 쪽이 양수**, pitch = asin(y) — **+Y가 위** **[판독]**.

### 속도 `VEL41` (0x71029064bc) — 탄 이벤트

```
vs = v * 60                      // 프레임당 → 초당
L = |vs|;  dir = vs/L (L > 0);   if L <= 1e-4 (0x38d1b717): dir = (0,1,0), L = 0
DIR25(dir)
S = (u32)( (L * (1/60) * 60) * (1/2048) * 65535 ), 상한 0xFFFF    → 16비트
dec: speed_per_frame = S/65535*2048/60 ... (read 함수가 역산)
```

범위 0~2048 단위/초, 0.03125 단위/초 단위. 기본 방향 `(0,1,0)`은 `[0x7105791978] → 0x7104a985b8` 의 `{0, 1, 0}` **[데이터]**.

### 속도 `VEL33` (0x7102906350) — PlayerNetState

`DIR21` + 크기 12비트: `(u32)(L * (1/60) * 60 * (1/128) * 4095)`, 상한 0xFFF. 범위 0~128 단위/초. 디코드(0x710241923c): `v_frame = dir * ((q/4095)*128 * (1/60) * 60) * (1/60)`.

### 가속 `ACC33` (0x7102906628) — AttackEvent

`a * 3600`(프레임² → 초²), `DIR21` + 크기 12비트 `(u32)(L * (1/3600) * 3600 * (1/1024) * 4095)`. 범위 0~1024 단위/초². 넉백 벡터로 보입니다 **[추정]**.

### 기타 형식 (PlayerNetState 등)

| 형식 | enc | dec |
|---|---|---|
| yaw13 (수평 방향 벡터) | `(x,z)` 정규화 → atan2Idx → `sgnmag(|θ|/π*4095, 12)` | sin/cos 표로 `(sin θ, 0, cos θ)` 복원 → +0x5c(x), +0x64(z), +0x60 = 0 |
| s12 `[-1,1]` | clamp(-1,1) → `round((v+1)*4095*0.5)` (반올림: ±0.5 더한 뒤 절삭) | `q/4095*2 - 1` (f64로 계산 후 f32) |
| u11 `[0,1]` | clamp(0,1) → `round(v*2047)` | `q/2047` |
| 정수 n비트 | 그대로 | 그대로 |
| 정수 +1 | `v+1` (−1 = 무효를 0으로) | `q-1` |
| s19 프레임 | `INT_MIN → 0x7FFFF` | `0x7FFFF → INT_MIN` |
| bool | `-(b & 1)` 1비트 | `!= 0` |
| 탄 이벤트 +0x38 | `(u32)(v*256 + 0.5)`, 11비트 | `q/256` (0~7.996; 1.5 → 384 → 1.5 실행 확인) — 의미 **[미확정]** |
| 고정소수점 오프셋형 (PlayerNetState_Jump +0x24/+0x28/+0x38) | `(u32)((v + B) * 65536 + 0.5)`, B = 100(24비트) / 200(25비트) | `q/65536 − B` (read 0x7102424998 대칭 추정) — 0x7102424728 판독 **[판독]**. `bitlayout.txt`의 u24/u25 표기는 이 형식 |

## 9. 웹 포팅

- 원본과 비트 호환이 필요하면 §3.4의 LSB 우선 패킹과 §3.5 헤더(23+4비트)를 그대로 쓰면 됩니다(`network_bitpack.py`의 `py_pack`이 원본과 비트 일치). 호환이 필요 없으면 같은 **양자화 단위**만 지키면 됩니다. 관측 가능한 차이는 위치 1/256 단위, 방향 0.044°/0.176° 단위, 속력 단위입니다. 원격 캐릭터·복제 탄의 위치가 원본과 같은 오차를 가지려면 송신 전에 `enc→dec`를 적용한 값을 **송신측도 자기 탄 시뮬레이션에 쓰는지**를 먼저 확인해야 합니다 **[미확정]** — 원본 발사 함수는 로컬 발사 때 양자화 전 값을 쓰는 것으로 보입니다(로컬 호출 인자가 이벤트 객체가 아님, 0x7102583ca8).
- 정확한 재현이 필요하면 atan/sin 표를 이미지에서 뽑아(`[0x7105794808]` 129×8 B, `[0x7105794810]` 256×16 B) 같은 보간을 구현합니다.
- 자바스크립트는 `Math.fround`로 f32 연산 순서를 맞추고, 절삭은 `Math.trunc`, 포화는 위 상한을 그대로 씁니다.
