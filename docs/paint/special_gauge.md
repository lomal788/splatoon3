# 스페셜 게이지와 칠 결과 집계

[paint_and_score.md](paint_and_score.md)의 하위 문서입니다. 칠한 양이 플레이어별 칠 포인트(p)와 스페셜 게이지로 들어가는 길, 게이지 비율이 HUD·네트워크로 나가는 길, 결과 화면 %(PaintPermille)를 정리합니다. 작업 지침은 [../../분석.txt](../../분석.txt), 표기는 [../README.md](../README.md#확정-수준-표기)를 따릅니다.

- 2026-10-02 작성([gauge]). 상태: **분석 진행**. 웹 구현 없음.
- 2026-10-02 갱신([paintgpu]): 요청 레코드 +0x6c 세팅·C_i 엔트리 GPU 값 의미(§4.2), 스페셜 시작 G+0x1c/+0x20 writer(§5), 결과 % 문자열(§6.9) 해소.
- 원본 실행: 원본 명령 구간 5개와 함수 1개를 unicorn으로 실행해 재구현과 비교했습니다(§10). 게임 전체를 실행한 검증은 아닙니다.
- 주소는 main NSO를 0x7100000000에 올린 기준입니다. 오프셋 앞에는 기준 객체를 씁니다.

## 4. 구조체

### 4.1 게이지 구조체 G (기준: 플레이어 본체 + 0xbd4)

같은 블록을 HUD는 `D+0xbd4..`로 읽습니다(D = 본체). 함수들은 `본체+0xbd4` 포인터를 인자로 받아 G 기준 오프셋으로 씁니다. 그래서 `str [x,#0xbe4]` 같은 본체 기준 쓰기 스캔(77곳)으로는 writer가 잡히지 않았습니다.

| G 오프셋 | 본체 오프셋 | 형식 | 의미(웹 권장 이름) | writer | reader |
|---|---|---|---|---|---|
| +0x00 | +0xbd4 | u32 | `paintTexels` 칠 텍셀 누계 | `0x7102483134`(+= C_i+4), 리셋 0 | 결과 `0x7103092a4c`, HUD |
| +0x04 | +0xbd8 | u32 | `gaugeTexels` 게이지 텍셀 | 가산(§6.2), 무기·사망·스페셜 종료 | 비율 계산 |
| +0x08 | +0xbdc | f32 | `gaugeFrac` 가산 소수 잔여 [0,1) | 가산 | 가산 |
| +0x0c | +0xbe0 | f32 | `gaugeExtraPerFrame` 매 프레임 추가 가산 | writer 미확정 | 가산 |
| +0x10 | +0xbe4 | f32 | `ratio` 0~1 | 비율 계산(로컬)/원격 복원/리셋 | HUD, 넷 송신, 사망 보존 |
| +0x14 | +0xbe8 | f32 | `specialPoint` 필요 p | `0x71024901c4`, 생성자 200.0 | 비율, HUD 키 |
| +0x1c | +0xbf0 | s32 | `specialFramesLeft` (>0 = 사용 중, ≥100000 = 시간 무제한) | 스페셜 시작 `0x71024a246c`(= 스페셜 객체 vt+0xa8), 매 프레임 −1, 종료 0x710246ec1c(0) | 비율, 아이콘, 넷 +0x8c |
| +0x20 | +0xbf4 | s32 | `specialFramesTotal` | 스페셜 시작 `0x71024a2468`(+0x1c와 같은 값) | 비율 |
| +0x24 | +0xbf8 | s32 | `chargeWait` 충전 대기(프레임) | 매 프레임 −1, 리셋 시 max(0,·) | 가산 조건 |
| +0x28 | +0xbfc | s32 | 시각(GameFrame+60) | `0x71024b42c4` | 미확정 |
| +0x2c | +0xc00 | u8 | 사망 시 보존 생략 / 사망 중 남은 프레임 정지 플래그 [추정] | | |
| +0x2d | +0xc01 | u8 | 무한 스페셜(디버그 명령 0x6c2b6a33, 미션 모드) [추정] | | |
| +0x2e / +0x2f | +0xc02 / +0xc03 | u8 | 게이지 강제 0 / 강제 가득 | | 비율 계산 직전 |

생성자(`0x710245717c` 안): G+0..+0x14 = 0, +0x14 = 200.0 **[판독]**.

### 4.2 플레이어별 칠 카운터 C_i (기준: 칠 시스템 + 0x5a708 + i×0xe18)

| 오프셋 | 형식 | 의미 |
|---|---|---|
| +0x00 | u8 | 리셋 요청(1이면 다음 갱신에 목록 비우고 0) |
| +0x04 | s32 | 이번 프레임 p용 텍셀 A |
| +0x08 | s32 | 이번 프레임 스페셜용 텍셀 B |
| +0x0c, +0x10 | f32 | A, B 누계 |
| +0x18 | 목록 | "p와 스페셜 둘 다" 엔트리 |
| +0x718 | 목록 | "p만" 엔트리 |

- i = `*(본체+8)+0x798`(플레이어 번호, 8 이상이면 0번 칸) **[판독]**.
- 엔트리 값 = GPU 결과(u32, `0x7101043cdc`가 하나씩 꺼냄) × 가중(+0x38). 가중은 도색 대상 종류(요청 레코드 +0x4c) 1·3이면 1.0, 2이면 `0x7102c1a7f0(셰이프)`(0이면 엔트리를 만들지 않음) **[판독]**.
- 어느 목록으로 갈지는 요청 레코드 +0x6c(u8): 0이 아니면 +0x18, 0이면 +0x718 **[판독]**. **+0x6c 세팅(해소, 2026-10-02 [paintgpu]) [판독]+[실행(에뮬)]**: 그리기 레코드 변환 `0x7102c11f80`이 `D+0x6c = (N+0x44 != 1)`로 씁니다. N+0x44는 요청 C+0(플레이어 칠일 때)이고, 탄 경로의 C+0 = !슬롯77 → 슬롯77이 0인 `spl::BulletSpJetpackLauncher`(제트팩)의 칠만 p 전용, 나머지 탄은 p+게이지입니다. 다른 도색 호출자(폭발·롤러 등 15곳)의 C+0 값은 **[미확정]** — [paint_and_score.md](paint_and_score.md) §3.5.2, §4.4.
- **엔트리 GPU 값의 의미(해소) [판독]**: 엔트리는 `0x7102c1461c`가 모드 4/5/6 스탬프 그리기를 `nvnCommandBufferResetCounter(1)` / `ReportCounter(1)`로 감싼 카운터입니다. 모드 4/5/6은 색을 쓰지 않고 스텐실 `NOTEQUAL 팀비트`(마스크 팀비트) + 셰이더 알파 테스트(내 팀 ≥ 0.3·최대)를 통과한 조각만 세며 통과한 곳의 스텐실을 팀비트로 바꿉니다. 따라서 **A = 그 프레임에 새로 내 팀 소유가 된 텍셀 수**(자기 땅 덧칠 0, 상대 땅 뺏기 포함, 같은 프레임 같은 팀 겹침은 한 번). 카운터 종류 1 = SAMPLES_PASSED라는 이름은 **[추정]** — [paint_and_score.md](paint_and_score.md) §3.5.4, §3.5.6.
- 합산 콜백 `0x7102c1adbc`(목록 +0x718: A만), `0x7102c1ae98`(목록 +0x18: A와 B) **[판독]**.

## 6. 계산식

### 6.1 필요 텍셀

```
full = fcvtzs(f32(G.specialPoint) * 211.2f)     // 200p → 42240, 190 → 40128, 180 → 38016
```
211.2 = 64(8×8 텍셀) × 3.3. p 환산과 같은 상수입니다([paint_and_score.md §4.2](paint_and_score.md#42-p-환산-판독)).

### 6.2 게이지 가산 (0x71024886c8 ~ 0x7102488e1c) **[판독]+[실행(에뮬 구간) 400/400]**

```ts
// 매 프레임, 생존이고 chargeWait 이 0 이하였을 때만
const rate = playerParam.alt ? altRate() : playerParam.specialIncreaseRate;   // +0xe8
let acc = f32(G.gaugeFrac + f32(rate * f32(C.texelsSpecial)));               // C_i+8 (u32→f32)
acc = f32(acc + (rule ? rule.autoInc(team) : 0));                              // 나와바리 0.0
acc = f32(f32(acc + playerParam.minorityUpPerFrame) + G.gaugeExtraPerFrame);   // +0x17c, G+0xc
let n = Math.trunc(acc); if (acc < 0 && acc !== n) n -= 1;                     // floor
G.gaugeFrac = f32(acc - n);
G.gaugeTexels = (G.gaugeTexels + (n >>> 0)) >>> 0;                             // 상한 검사 없음
```

## 9. 웹 포팅

```ts
interface SpecialGauge {        // 원본 G (본체+0xbd4)
  paintTexels: number;          // u32
  gaugeTexels: number;          // u32, 상한 없음
  gaugeFrac: number;            // f32
  gaugeExtraPerFrame: number;   // f32
  ratio: number;                // f32
  specialPoint: number;         // f32
  specialFramesLeft: number; specialFramesTotal: number; chargeWait: number;
  forceEmpty: boolean; forceFull: boolean; infinite: boolean;
}
interface PlayerPaintCounter { texelsPoint: number; texelsSpecial: number }   // C_i +4/+8
```

순서(1 프레임): 칠 GPU/CPU 격자 갱신 → 카운터 C_i 집계(엔트리 값 = 바뀐 텍셀 × 가중, half-away 반올림) → 플레이어마다 `paintTexels += C.texelsPoint` → (생존·대기 0) 가산 §6.2 → 비율 §6.3 → 4프레임마다 % 송신 → HUD.

- 연산은 모두 f32: `Math.fround`를 연산마다 적용(구간에 FMA 없음, 에뮬과 비트 일치 확인).
- 웹 CPU 격자([paint_and_score.md §6](paint_and_score.md#6-웹-포팅-구조))의 2단계(소유 스텐실 NOTEQUAL + 알파 테스트) 통과 수를 요청 소유자(N+0 플레이어 번호)의 C에 넣고, 요청의 N+0x44 == 1(제트팩 등)이면 texelsPoint만, 0이면 texelsPoint와 texelsSpecial 둘 다 늘립니다 **[판독]**.
- 원격 플레이어는 % 만 유지하고 §6.6 복원식을 씁니다.
