# ColPaint: 지형 도색 아틀라스 생성

지형(충돌 메시)에 칠할 때 쓰는 도색 텍스처의 UV 아틀라스를 원본이 **실행 중에** 어떻게 만드는지 정리합니다. 상위 문서 [paint_and_score.md](paint_and_score.md) §3.2, 표기 규칙 [../README.md](../README.md#확정-수준-표기).

상태: **분석 진행(4차, [paint4])**. 프리즘 분류·기저·슬랩·정점 공유·패널 병합·재투영·패킹은 원본 함수 unicorn 실행과 재구현이 일치합니다(§9). 패널 연결(띠)·패턴 인식·시각 모델 매핑은 개요만 판독했습니다. 2026-10-03 [r5 paint]: 런타임 칠 경로(월드 → 패널 좌표 → 시드 위치, 회전·높이 마스크·초기화) §7.1 추가, 좌표 변환 원본 실행 6000/6000.

## 3. 전체 흐름

```
충돌 대상 목록(ColPaintProcTarget::TargetCollisionList)
 1. 프리즘 추출: 삼각형마다 0x7102c0725c → (방향 클래스 d, 꼭짓점 3, 슬랩 비트) → 방향별 버퍼(42 × 최대 8000)

 3. 패널 병합: 같은 방향에서 (u,v) AABB 겹침 && (깊이 중심 차 < 0.2 || 깊이 범위 겹침)
 4. 패턴 인식·연결(띠 구성)·모델 메시 보정  ← [미확정]

```

빌드 스레드 이름 `ColPaintThread`, 모든 단계가 `ColPaintMgr+700 & 1`(중단 플래그)이면 루프를 빠져나옵니다 [판독].

## 4. 프리즘(삼각형) 분류

### 4.1 메시 삼각형 콜백 `0x7102c0725c` [판독]+[실행 5103/5103]

```
mat = 삼각형 재질 레코드(+0x88): u32 MaterialCollection 인덱스, u64 UserShapeTag 마스크(+8)   // bphsh 재질표 16 B와 같은 배치
if mat.index ∈ {21 Fence, 22 RopeNet}: 버림
v0..v2 = 충돌 강체 3×4 행렬 × 꼭짓점          // 행 우선, x' = m3 + x·m0 + y·m1 + z·m2
n = normalize((v1−v0) × (v2−v0)); |n| == 0 이면 버림
d = classify(n); d == 0xff 또는 mask bit50(ForceColPaintNotPaintable) 이면 버림
mask bit48(ForceColPaintYPlus) 이면 d = 0x28
prism = {+0x08 v0, +0x14 v1, +0x20 v2, +0x2c slab(d), +0x30 충돌, +0x38 삼각형 번호, +0x40 패널(0)}
```

- 비트 번호는 PhiveConfig UserShapeTag 의 MaskValue와 같습니다(48 YPlus, 49 Paintable, 50 NotPaintable) **[데이터]**. 이 콜백은 bit49(Paintable)를 보지 않습니다 **[판독]**.
- 물(Water, MaterialCollection 2) 삼각형은 이 콜백에서 걸러지지 않습니다. Yagara 물 평면(y=−0.05, 면적 44 662)이 칠 대상이 되는지는 대상 충돌 목록 구성(어떤 충돌을 넣는지)에 달려 있고 이번에 확인하지 못했습니다 **[미확정]**.
- 씬 이름이 `"PlayerTest"`면 플래그를 하나 켭니다(용도 미확인).

### 4.2 방향 클래스 `classify` = 0x7102bd7918 [판독]+[실행 8000/8000]

```
n = normalize(n)
if n.y > 0.999: return 0x28                      // 위
e = atan2f(−n.y, sqrt(1 − n.y²))                 // e + π/2 = n 과 +Y 의 사이각 θup
k = (uint)(int)((e + 1.5707964 + 0.3926991) / 0.7853982) % 5
c = k==1 ? (e + 1.5707964 <= 0.7853982 ? 2 : 3) : (k<2 ? k+1 : k+2)
if c == 6: return 0x29                           // 아래
az = (int)((atan2f(−n.x/h, −n.z/h) + 3.1415927 + 0.3926991) / 0.7853982) & 7    // h = |n.xz|, h < 1.19e-7 이면 0xff
return az + c·8 − 8
```

| 클래스 | θup 범위 | 대표 법선 극각 φ | 투영 평면 |
|---|---|---|---|
| 0x28 | n.y > 0.999 | 0 | 수평(회전 θ = −45°) |
| 0..7 | [0°, 22.5°) | 0 (기저는 정확히 (0,1,0)) | 수평, 방위 8가지로 회전한 축 |
| 8..15 | [22.5°, 45°] | 33.75° | 경사 |
| 16..23 | (45°, 67.5°) | 56.25° | 급경사 |
| 24..31 | [67.5°, 112.5°) | 90° | 벽 |
| 32..39 | [112.5°, 157.5°) | 135° | 처마 아래 |
| 0x29 | [157.5°, 180°] | 180° | 천장 |

방위 az(0..7) = 45° 단위, 법선 수평 성분이 (sin(az·45°), cos(az·45°)) 방향 **[판독]**.

### 4.3 기저 `basis` = 0x7102bd7b2c [판독]+[실행 45/45]

```
d > 0x29: 단위 행렬
d < 8   : B2 = (0,1,0); θ = (d&7)·45°; B1 = normalize(−sinθ, 0, −cosθ); B0 = B1 × B2
그 밖   : θ = (d∈{0x28,0x29}) ? −45° : (d&7)·45°;  φ = 위 표
          B2 = (sinθ·sinφ, cosφ, cosθ·sinφ); B0 = normalize(up × B2) (길이 < 1.19e-7 이면 (1,0,0)); B1 = B2 × B0
패널 좌표: u = B0·p, v = B1·p, w(깊이) = B2·p
```

### 4.4 깊이 슬랩 `slab_mask` = 0x7102c0638c [판독]+[실행 2000/2000]

```
n' = (sinθ·sinφ', cosφ', cosθ·sinφ')   // φ' 은 위 표와 같되 d < 8 은 φ' = −45° (기저 함수와 다름, 원본 그대로)
k_i = clamp((int)((n'·v_i + 200) / 6.25), 0, 31)   // 32칸 × 6.25 = [−200, 200)

```

## 5. 패널

### 5.1 패널 추출 0x7102bf7ce8 + 이웃 콜백 0x7102bf92cc [판독]+[실행]

- 방향 d 마다 프리즘 AABB 전체(±0.1)를 범위로 **깊이 3 옥트리**(0x710111e5c0)를 만들고 각 프리즘을 AABB가 들어가는 칸(모턴 코드, 0x710111ea64)에 넣습니다.
- 프리즘 P(아직 패널 없음)마다 P의 AABB±0.1 로 질의(0x710111e8c4)합니다. 질의는 **질의 상자가 들어가는 칸, 그 조상, 그 자손**만 봅니다(형제·이웃 칸은 보지 않음) **[판독]**.
- 이웃 Q 판정: `Q != P && (Q.slab & P.slab) != 0 && touch(P,Q)`. `touch` = 0x7102c05444, 9쌍 정점 거리 중 하나라도 < 0.001 **[실행 2000/2000]**.
- 합치기: Q가 패널이 있으면 P를 그 패널에 넣고(이미 P 패널이 있으면 P 쪽 패널을 Q 패널로 옮긴 뒤 삭제), Q가 패널이 없으면 P 패널(없으면 새로 만듦)에 Q를 넣습니다. 이웃이 하나도 없으면 P 혼자 새 패널.
- 패널 객체 0x1f0 B(생성 0x7102bec990): +0x20..+0x34 (u,v,w) AABB(min3, max3), +0x38 방향, +0x3c..+0x50 매핑 AABB, +0x54 매핑 방향(초기 0xff), +0x58 프리즘 목록(+0x68 개수), +0x9c 패턴 번호, +0xa0/+0xb0/+0xb8 연결, +0x1d0 자기 자신. 프리즘 추가 0x7102bece04 가 AABB를 넓힙니다.

**결과 차이 [실행]**: Fld_Yagara 프리즘 4599개 → 원본 1174 패널, 완전 연결 성분(재구현 `extract_panels`) 1139. 원본은 옥트리 질의가 형제 칸을 보지 않아 **칸 경계를 넘는 정점 공유를 일부 놓칩니다**(예: dir 0x1e 프리즘 126·127, 정점 (−13.5,6.0,13.5) 공유인데 다른 패널). 같은 분할로 끝난 패널은 방향·AABB가 비트 단위로 일치합니다. 웹에서 원본 분할을 그대로 쓰려면 옥트리 질의 규칙까지 구현해야 합니다(§8.2).

### 5.2 패널 병합 0x7102bf88d0 [판독]+[실행]

같은 방향 목록에서 패널 A(앞에서부터, 이미 흡수된 것 제외)에 대해 모든 B를 보며
`B.u 범위 ∩ A.u 범위 ≠ ∅ && B.v ∩ A.v ≠ ∅ && (|A.w중심 − B.w중심| < 0.2 || w 범위 겹침)` 이면 B를 A에 합치고(A가 커짐) A를 처음부터 다시 검사합니다. 흡수 표시 비트는 앞 5120개만 있습니다. Yagara: 원본 1174 → 1016.

### 5.3 패널 수 상한

방향별 버퍼 5120, 런타임 Col 대상 id < 5·1024 = 5120(`id >> 10 < 5`, 0x7102c4a6bc 등) **[판독]**. 패널 id 체계(전역 번호 매기기)는 0x7102c00150 의 vt+0x28 호출이 정합니다 **[판독-부분]**.

## 6. UV 매핑과 텍셀 밀도

### 6.1 아틀라스 크기 [판독]

```
S = (DAT_71058a8da0+0xe0 문자열 == 현재 씬 이름(FUN_7101323040()+0x2d8)) ? 200 : 400   // 비교 대상 씬은 [미확정]
atlas = S·8 = 3200 텍셀(또는 1600), UV = 텍셀 / (S·8)
초기 빈칸(0x7102c0ec20): 씬 "Msn_A05_07C" 면 4×4 타일, 아니면 (0,0)–(3200,3200) 하나
```

Col 대상의 PaintTextureData size도 (S,S)입니다(0x7102c3f0c4의 Col 전체 대상 = 400 또는 200) → tex0 3200×3200 **[판독]**.

### 6.2 패널 한 장의 텍셀 사각형 [판독]

- 크기 = `ceil((max−min)·8)` (u, v 각각; 원본 올림은 `(int)x + (x ≥ 0 && x != (int)x)`).
- 수평 묶음(0x7102bfda20, 방향 0x28 또는 0..7 패널을 연결로 묶음): 각 패널 매핑 AABB를 **0x28 기저로 재투영**(0x7102bf9850, §6.4)한 뒤 `중심·8 ± 크기/2` 에 둡니다. 즉 수평면은 방위 클래스와 무관하게 **월드 XZ를 그대로 8배**한 좌표로 이어 붙습니다. 묶음 크기 = ceil(전체 max − min).
- 벽 등 띠(0x7102bfe07c, U 또는 V 방향): 패널을 연결 순서로 이어 붙이고, 이웃 패널은 방향 차이 회전(0x7102bd7ec8)과 공유 모서리 위치(0x7102bfd864, 연결 표 +0xb8)로 옆에 둡니다. 패널마다 `+0x54 = +0x38`(자기 방향 기저). **세부 [판독-부분]**.

### 6.3 묶음 → 아틀라스 [판독]

```
묶음 크기 = (max + 3) − (min − 3)        // 사방 3 텍셀 여백
세로 < 가로 이면 90° 회전(cos 90° = −4.371139e-08 그대로 곱함)해 세로가 길게
묶음 한 변이 S·8 보다 크면 묶음을 풀어 영역별로 다시 넣음(0x7102c03338)
정렬: 묶음 목록을 max(가로,세로) 내림차순 안정 병합 정렬(0x7102c04f48)
패킹: 아래 §6.5, 실패한 묶음은 UV 없음
패널 UV 행렬(패널+0x18 객체, 2×3) = (묶음 위치 + 묶음 내 변환 · 8 · 패널(u,v)) / (S·8)   (0x7102bfd3e4)
```

### 6.4 매핑 AABB 재투영 0x7102bf9850 [판독]+[실행 2000/2000]

원래 AABB의 **중심**과 매핑 AABB의 **반경**으로 만든 상자의 8 꼭짓점을 `M[k][i] = A_i·C_k`(A = 원래 방향 기저, C = 새 방향 기저)로 옮겨 새 AABB를 만듭니다. 방향이 같거나 매핑 AABB가 비면 방향 바이트만 기록합니다.

### 6.5 기요틴 패킹 0x7102c105bc [판독]+[실행 2075/2075]

```
빈칸 목록 = 높이 오름차순(같은 높이는 먼저 들어온 것이 앞, 0x7102c104f8)
w·h > 0 이 아니면 실패
목록 앞에서부터 w ≤ 빈칸 가로 && h ≤ 빈칸 세로 인 첫 빈칸 R=(x0,y0,x1,y1) 의 (x0,y0)에 배치
if (x1−x0−w) ≤ (y1−y0−h):  위 (x0, y0+h, x1, y1),  오른쪽 (x0+w, y0, x1, y0+h)
else:                       위 (x0, y0+h, x0+w, y1), 오른쪽 (x0+w, y0, x1, y1)
넓이 ≥ 1 인 것만 (위 → 오른쪽 순서로) 정렬 삽입, R 삭제
```

## 7. 런타임에서의 쓰임 (관련 판독 요약)

- 도색 요청의 Col 대상 id = 패널 id. 같은 요청은 분배 1회 안에서 패널마다 한 번만 칠합니다(중복 비트 0x1400개) — [paint_and_score.md](paint_and_score.md) §3.5.1.
- 패널 런타임 레코드(관리자+0x2c0 → +0x398[id]): +0x3c..+0x50 매핑 AABB, +0x54 매핑 방향. 0x7102c3f0c4 는 요청 크기를 `(Δu + 0.875, Δv + 0.875)`, 위치를 매핑 AABB 중심으로 채우고, 0x7102c4a6bc 는 위치를 매핑 방향 기저(0x7102bd7b2c)로 패널 좌표로 바꿉니다 **[판독]**.
- 시각 메시에 도색이 보이는 경로(setupMapModel_, 0x7102b71960/0x7102b71fd8 계열)는 [gfx4] 영역과 겹쳐 이번에 판독하지 않았습니다 **[미확정]**.

### 8.2 동등성

- **반드시 같게**: 방향 분류(§4.2 f32 순서 그대로), 기저(§4.3), 8 텍셀/단위, 올림 규칙, 펜스·로프넷·NotPaintable 제외, YPlus → 0x28. 이것들이 텍셀 수(=점수 d)를 정합니다.
- **같게 하면 좋음**: 패널 분할(옥트리 질의 규칙 포함), 병합, 여백 3, 회전, 정렬·패킹. 이음매 모양과 띠 이어 붙이기(벽 모서리에서 자국이 끊기지 않는 것)가 여기서 결정됩니다. 패킹 위치 자체는 점수와 무관합니다(텍셀 위치만 바뀜) **[추정]**.
- 재구현 도구 `paint4_colpaint.py`는 패널 추출을 **완전 연결 성분**으로 하므로 원본보다 덜 쪼갭니다(Yagara 1139 vs 1174). 원본과 같게 하려면 옥트리(0x710111e5c0 범위 ±0.1, 깊이 3, 모턴 코드 0x710111ea64, 질의 0x710111e8c4 = 칸·조상·자손만)를 그대로 옮기거나, `paint4_emu.py`의 원본 실행 결과를 빌드 데이터로 쓰면 됩니다.
