# 환경 세트 전환의 진행도 생산과 종료

## 1. 기능 개요

환경 보간에 전달하는 t는 달력·낮밤 시각을 직접 읽은 값이 아니다. 전환 요청이 정수 길이 N과 카운터 c를 초기화하고, 자원 준비가 끝난 갱신마다 c를 하나 증가시킨다 [판독]. 실제 t 및 종료 처리를 원본 함수 3,078건으로 확인했다 [실행].

## 2. 원본·근거

Splatoon 3 v0. SHARED/FUNCS/index 대조 후 새 env_transition_writer.c(2b5af20),env_transition_callers.c(2d3d240/2d3d3a0)를 읽고 기존 gfx4/g2_apply.c의 실제 전체 시작2b5c250을 연결했다. 도구 web/tools/r8_gfx_env_transition_emu.py, 결과 analysis/completion/r8/env_transition_emu.json. 2b5c4a8은 이 함수의 중간 주소다.

## 3. 입력과 요청 [판독]

2b5af20(duration,obj,selector)는 현재+570을 먼저+578에 저장한다. selector0/1/2는 각각 obj+438/+508/+4A0을 새+570으로 쓴다. 다른 selector는 이전 포인터 저장 뒤 반환한다. 새 포인터가 이전과 같으면 길이·카운터를 재설정하지 않는다. 다른 포인터이면 +584=N=int(duration),+580=c=0으로 쓴다. float→signed integer 절삭을 사용하며 ceil 또는 초×60 변환은 없다. 세 세트의 이름은 이 함수만으로 낮/밤/황혼이라고 부르지 않는다.

직접 BL 호출자는2d3d240/2d3d3a0이다. 전자는1.0을 전달하고 후자는 인수 길이를float로 전달한다. 이 호출자들의 협동 모드 실제 행동은 이번 사격장 범위에서 확장하지 않았다.

## 4. 상태 필드 [판독]

| object offset | 값·수명 |
|---|---|
| +570/+578 | 새 세트/이전 세트 포인터 |
| +580/+584 | signed32 카운터 c/길이 N |
| +6D1 | 요청 자원의 준비 판정 캐시 |
| +6D0 | 추가 하늘 모델 교체·알파 처리 사용 |

## 5. 조기 반환과 지연 [판독]

갱신2b5c250은 공통 컴포넌트 갱신10bf154 뒤 c>=N, 이전포인터null, 새포인터null이면 반환한다. 6D1=false이면 원본 자원 핸들로 준비 상태를 확인하며, 아직 준비되지 않았으면 카운터를 증가시키지 않는다. 따라서 N은 준비된 갱신 횟수이며 외부 시간의 일정한 진행을 자동 보장하지 않는다.

## 6. 보간식과 순서 [실행]+[판독]

N==1이면 t=1. 다른 N에서는 float32(c)/float32(float32(N)-1)이다. 클램프·smoothstep을 추가하지 않는다. 2b5fe88(t,new,activeEnvironment,old) 호출 뒤 c++ 한다. N=2는0,1; N=3는0,.5,1이다. 정상 c=0..N-1의 N회 호출에서 끝점을 포함한다. 카운터가 음수인데 N보다 작으면 원본은 음수 t를 만들 수 있다(해당 음수 진입은 식 판독, 정상 범위 실행과 구분).

## 7. 종료·복구 [판독]+[실행]

증가된 c>=N이면 이전포인터578을0으로 지운다. 추가 모델 분기가 사용되면 이전 모델 핸들을 처리하고6D0을0으로 지운다. 새 경로590을628로 capacity-1까지 복사하고, 새 변환59C..61B를 이전634..6B3에 복사한다. 이 종료 복사와 포인터 제거는 같은 갱신 뒤에 일어난다.

## 8. 표현 연결 [판독]

2b5fe88과 각 apply 함수의 기존 원본 식에 위 t가 전달된다. 추가 하늘 모델 경로에서는 이전 모델 alpha에1-t, 새 모델에1을 공급한다. 이를 모든 모델의 대칭적인 alpha crossfade라고 바꾸지 않는다. 로비가 전환 요청을 생성하는 모든 조건과 전체 GPU 화면은 이 진행도 질문과 별도로 남겨 둔다.

## 9. 웹 반영 필요

impl/render.md/assets.md: 이전의 외부 낮밤 시각 추정 대신 요청 상태(old,new,N,c,ready)를 보존한다. 원본 f32 보간과 자원 준비 시 카운터 정지, N==1, 종료 복사 순서를 반영해야 한다. 웹 코드와 impl 문서는 변경하지 않았다.

## 10. 실행 검증

python web/tools/r8_gfx_env_transition_emu.py → 정상3,072건의 t 비트·apply 인수·카운터·종료포인터 및 조기반환6건 전부 일치. 외부 공통 컴포넌트 스케줄러만 no-op, apply는 원본 t를 받는 기록 sink, libc 복사는 바이트 동일 서비스다. 수학·카운터 알고리즘 스텁은 없다. 준비flag=true, 추가모델분기false인 합성 상태의 실행이며 실제 자원 대기/하늘 모델 재생을 실행했다고 하지 않는다.

## 11. 정정·남은 한계
