# 모델 LOD 임계 소비와 단계 선택 (v0)

## 1. 기능 개요와 화면 동작

모델 LOD는 원본 임계 레코드를 뷰별로 읽어 단계를 정한다. 거리 방식에는 이전 단계를 유지하는 히스테리시스가 있다. 단순히 모델 원점과 카메라의 유클리드 거리를 재서20/50에서 바꾸는 구현과는 식이 다르다 [판독]. 정적 모델의 전체 CPU 패킷은 원본 실행으로 대조했다. 애니메이션 모델의 경계구별 경로는 원본 명령/함수 판독이다. GPU 디더 픽셀 실행은 이번 검증에 포함하지 않는다.

## 2. 원본·버전·자료 위치

Splatoon3 v0 `extracted/exefs/main.reloc.img`; 기존 `render/r4_lod.c`는 임계 표 선택 근거로 재사용한다. 새 C는 `analysis/decomp/r8_graphics/{bfres_lod_model,model_lod_generic,model_lod_packet,lod_selector,lod_game_configuration}.c`. 실행은 `web/tools/r8_gfx_lod_emu.py`와 `r8_gfx_lod_draw_emu.py`, 결과는 `analysis/completion/r8/lod_emu.json` 및 `lod_draw_emu.json`이다. 후속 새 C는 `lod_mapping_geometry.c`, `lod_dispatch_key.c`, `lod_queue_build.c`, `lod_shape_draw.c`다.

## 3. 진입점과 호출 흐름

- 생성: BfresModel VT`0x7105727180`의`+0x228`는`0x710368fb34`로, 모델`+0x118`의 바이트를 **레코드 개수**로 돌려준다. 이 바이트를 bool이라 단정할 근거는 없다. 실제 생성`0x7103689a28`이 이 개수로 반복하며`0x7103777354`가 모델`+0x38`의 레코드 배열을 할당한다 [판독].
- 원본 임계 적용`0x71010fe270`은 각 레코드에`[Start,2·Start−End,1/(End−Start)]`를 쓴다(기존 판독). 재계산`0x710377e054`는 첫 두 값의 역차를 다시 쓴다 [새 판독].
- 정적 모델 경로`0x7103777f28`, 애니메이션/경계구별 경로`0x710377e3a8`이 같은 선택기`0x7103788760`을 호출한다. 다른 특화 경로의32개 BL도 같은 선택기를 호출하므로 단계 계산 리프의 식을 공유한다 [판독].
- 게임 초기화`0x71010fdd90`이 거리 방식 전역을1, 히스테리시스 폭을10.0으로 쓴다. 매 프레임`0x710121d910`은 camera/query type4 객체의 가상`+0x30` float가0.9 미만이면 전역 거리 보정을25.0, 그 외0.0으로 쓴다 [판독]. 이 getter의 고수준 명칭은 아직 단정하지 않는다.

## 4. 구조체·필드·상수

모델`M`, 레코드`R=M[+0x38]+viewIndex·0x50`, 선택기 입력`U=R+0x30`(정적)/경계구의 뷰별0x20레코드(애니메이션)이다.

| 위치 | 확인된 쓰임 |
|---|---|
| `R+0/+4/+8` | Start/2Start−End/역간격 |
| `R+0xc/+0x10/+0x14` | 화면 크기 방식의 기본 임계0.25/0.125/0.0625 |
| `U+8` | 단계 바이트 저장 위치 포인터; 기본`U+0x10` |
| `U+0x10/+0x11 bit0` | 현재 단계/갱신 고정 플래그 |
| `U+0x14/+0x18` | 경계구 화면 크기/뷰 공간 Z |
| `M+0x23/+0x24` | 단계 개수/최종 패킷에 더하는 단계 오프셋 |
| 전역`5999d58/d5c/d60` | 거리 방식 활성/거리 보정/히스테리시스 폭 |

생성`3689a28`은 셰이프 리소스`+0x5b`의 최대 메시 개수를 구해 Model VT`+0x268`=`112d428`로`M+0x23`에 쓴다 [판독]. 즉 단계 개수를 고정3으로 가정하지 않는다. Player00의3개 메시 LOD 데이터 자체는 기존 BFRES 데이터 근거다.

## 5. 상태 전이와 수명

고정 플래그가1이면 아무 것도 바꾸지 않는다. 저장 위치가 외부 포인터면 외부 단계와`count−1`의 작은 값을 내부 단계 바이트에 복사한다. 기본 내부 저장 위치에서는 거리/화면 방식으로 새 단계를 계산한다. 거리 방식의 히스테리시스 분기는 이전 단계가 새 하한 단계 또는 히스테리시스 없는 상한 단계와 같으면 그대로 유지한다 [판독]+[실행].

## 6. 계산식과 상세 의사코드

모든 아래 덧셈·뺄셈·곱셈은 원본 개별 f32 명령 순서다. FMA로 합치지 않는다. 경계구`B=(x,y,z,r)`, 뷰 행렬 행`V[0x20..0x2c]`에서

```text
zView = ((V20*x + V24*y) + V28*z) + V2c
screenRadius = FLT_MAX                      if zView >= 0
screenRadius = (r * -Vf8) / zView           otherwise
T = ((zView + Start) + r) + globalBias
q = (viewRecord[+8] - T) * inverseGap
```

`viewRecord[+8]`은 선택기 float 인자로 그대로 전달하는 원본 입력 필드다. 이름이나 항상0이라는 값으로 바꾸지 않는다. 경계구의 뷰 공간 Z와 반경을 사용하므로 원점 거리로 교체하지 않는다.

거리 방식에서 `count<2` 또는 `viewRecord[+8]<=T`면 최소 단계로 간다. 히스테리시스0 이하인 경우 `q<=1`이면`trunc_f32(q*(count−2)+1)`, 그 밖 마지막 단계다. 폭이 양수이면 `lo=q−inverseGap*h`; `lo>1`이면 마지막 단계, 그렇지 않으면

```text
new = max(minimum, trunc_f32(lo*(count−2)+1))
hi  = trunc_f32(q*(count−2)+1)
if old != new and old != hi: old = new
```

화면 방식은 뒤 임계부터 `screenRadius<threshold`를 검사하고 처음 충족하는 단계 바이트를 쓴다. 이 경로에는 count와 같은 단계 값이 나올 수 있다. 원본을 더 자연스럽게 고쳐 count−1로 미리 자르지 않는다 [판독]+[실행]. 정적 패킷의 바이트`+0x26`은 별도로`min(count−1,modelOffset+selected)`로 자른다. **후속 소비 판독 정정(2026-10-03)**: 이 바이트는 큐의 두 번째 24 B 항목(패킷의`+0x26`→항목`+0x17`)에 전달한다. 일반 메시 항목은 패킷`+0x25`의 원래 선택 단계를 사용한다. 이전에`+0x26`을 모든 메시의 최종 단계로 부른 설명은 두 큐를 구분하지 못했으므로 정정한다.

## 7. 애니메이션·에셋 연결

애니메이션 경로`377e3a8`은 경계구 객체`+0x98..0xa4`의 중심/반경을 뷰 공간으로 바꾸고, 경계구별 뷰 레코드`[shape+8]+viewIndex·0x20`를 선택기 입력으로 사용한다. 임계 입력은 그대로 모델의0x50 레코드다. 선택 단계는 드로 항목 바이트`+0x18`에 복사한다 [판독]. 정적 경로는 패킷`+0x25`에 선택 단계,`+0x26`에 위 최종 단계 값을 쓴다 [판독]+[실행]. 실제 GPU 메시 발행과 디더 혼합의 모든 변형은 이번 실행 범위 밖이다.


### 7.1 플레이어 이름 → Default [판독]+[데이터]+[실행]

새 `10fde9c`은 RSDB 관리자`5999b420`의 9번째 레코드(stride0x28, offset0x140)의 행 키를 순회한다. `38c9e50`→`38a41d8`이 `Work/Gyml/<이름>.game__gfx__parameter__LODThreshold.gyml`에서 이름을 추출하고, `0f7694c` 해시를 노드`+0x20`, 같은 이름을`+0x30` 문자열에 넣는다. 별도 모델 이름→다른 행 이름 매핑 데이터가 아니다. 36행은36개의 같은 이름 키로 구성된다 [판독]+[데이터].

BfresModel VT`+0x28=368f030`은 모델`+0x100`의 리소스`+8` 문자열 포인터에2를 더한다. BFRES FMDL의 길이 접두2 B 뒤 **모델 이름**을 돌려준다. 실제 압축 원본7개를 메모리에서 해제해 읽은 이름은 `Player00`, `Player00_Hlf`, `Player01`, `Player02`, `Player02_Hlf`, `Squid`, `Octopus`다. 모두 위36키에 없고 접두/접미 예외에도 해당하지 않아 `Default`를 받는다. `_Hlf`도 같은20/50이다. FRES 파일 이름 `Player_Squid`를 FMDL 이름 `Squid`로 혼동하지 않는다.

원본 파서36키와 원본`10fe270`의 이름 분기48건(36이름+실제7모델+접두/접미5예외)을 실행했다. 매 건 행 선택과12 B `[Start,2Start−End,inverseGap]`를 대조해 불일치0. 행 로더는 원본 JSON의 행을 공급하는 리소스 경계다. 이름 트리는 원본에서 추출한36키/원본 해시로 구성한 fixture이며, 전체게임 RSDB 적재 실행은 아니다.

### 7.2 패킷 → 큐 → 실제 메시 [판독]+[실행]

`377d268`은`572d398` 함수 테이블로 LOD 패킷을 만들고, 해당48 B 패킷의`+0x18`부터를 `5727d00` 테이블의 `36ab4e8/36ab858/36abc20/36ac044`에 전달한다. 각 함수는 메시 큐 항목`+0x17` 상위 비트에 일반 단계(패킷`+0x25`)를 넣으며, 두 번째 항목은 별도 단계(패킷`+0x26`)를 쓴다. 낮은 비트2..3은 셰이프의 렌더 구분이다.

실제 큐 소비`36ba1a0`은 항목`+0x17`의 비트4..6을 꺼내 셰이프 VT`+0x60`으로 넘긴다. BfresModel 셰이프 VT`5727f08`에서 이는 `36bf13c`다. 이 함수는 `shape+0x18` 비트4..6의 메시 개수보다 단계가 작은지 확인하고, 선택한 `ResShape[+0x18]+stage·0x38` 메시를 `089153c`에 전달한다. `089153c`는 선택 메시의 서브메시 오프셋/인덱스 수/형식/firstVertex를 `083db68` GPU 명령 발행 경계에 넘긴다. 메시 단계는 이름이나 거리에서 다시 근사하지 않는다.

원본 생성`3689a28`이 `FSHP+0x5b`의 MeshCount를 셰이프`+0x18` 상위 비트에 직접 쓰는 것도 확인했다. 7개 원본 모델의 첫 몸 셰이프 MeshCount는 모두3이고, 예 Player00 몸 인덱스 수는 단계별9600/5214/2433이다. 각 모델의 실제 Mesh/서브메시 데이터를 fixture에 복사해 단계0..2×렌더 구분4×인스턴스 수1..3으로 원본 큐252건과 원본 큐소비→실제메시 함수→발행 인자252건을 대조했다.72 B 큐 항목 전체 및 명령 인자 모두 불일치0.

`36ad36c`의 셰이더/재질 상태 바인딩은 호환되는 fixture 상태로 승인 반환했다. GPU 버퍼 주소 조회와 최종 명령 발행은 명시한 외부 경계다. **LOD 선택·메시 인덱싱·서브메시 계산은 스텁하지 않았다.** 원본 GPU에 그려서 픽셀을 비교한 결과는 아니며, 동적 포즈 경계구와 셰이더 디더 페이드는 이 실행과 구분한다.

## 8. 다른 기능과의 상호작용·정정 기록

2026-10-03: 이전 문서의 유닛 VT 미식별/거리 reader 미발견을 위 생성→리프→패킷 근거로 정정한다. 첫 후보 조사에서`LDRB`만 보고`368fb34`를 bool로 배제한 것은 잘못된 해석이었다. 모델 생성의 반복 개수 사용이 직접 반증한다. 기존 Start/End 역해석 정정은 유지한다. 당시 Player 이름 override/3단 메시 연결은 부분 해소로 남겼다. 후속`10fde9c` 이름 적재와`36ab4e8→36ba1a0→36bf13c→089153c`실제 소비로 이 연결을 해소한다. GPU 픽셀/디더 혼합까지 실행했다는 뜻은 아니다.

## 9. 웹 포팅 구조와 구현 순서

`impl/assets.md`/`impl/render.md`의 LOD0 고정 및 단순 거리 LOD 근사에는 모델/경계구 뷰 Z, 반경, 뷰 입력 필드, 전역 보정, 이전 단계 상태를 전달해야 한다. 화면 방식 단계와 별도 단계 오프셋의 clamp를 구분한다. 실제 FMDL 이름으로 임계 행을 찾고, 일반 메시 단계와 두 번째 큐의 단계를 각각 전달해야 한다. 이번 작업에서 구현/impl 파일은 변경하지 않았다.

## 11. 미확정과 다음 근거

거리 reader·단계식, 실제 플레이어7모델 Default 적용,3단 실제 Mesh 연결은 해소했다. `viewRecord+8` 생산과 고수준 이름, type4 getter 명칭, 동적 포즈 경계구의 전체 실행, Hoian SLOD/디더 페이드의 게임 writer와 GPU 픽셀은 미확정이다. 새 큐는 선택단계를 실제 메시로 전달하는 discrete 경로를 보여 주지만, 이것만으로 다른 셰이더 디더 옵션이 항상 꺼졌다고 주장하지 않는다. 다음은 ModelScene 뷰0x7f0 레코드 writer, shader SLOD 옵션 공급과 관련 draw state이다.
